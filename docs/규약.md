# 공통 규약 (moim/common)

모든 기능은 아래 규약을 `moim/common` 의 함수로만 따른다. 기능 파일 안에서 같은 계산을 따로 만들지 않는다.

## 1. 금액
- 원 단위 정수로 저장한다. 입력의 쉼표·"원"은 지운다(`money.to_won`).
- 소수점은 사사오입한다: 2.5 → 3, 3.5 → 4, 2.4 → 2 (`rules.ROUNDING = "HALF_UP"`).
- 0원 이하 지출은 받지 않는다.

## 2. 나누기와 나머지 1원
- `money.split(금액, 참여자, 낸 사람, 비율)` 하나로 나눈다. 결과 합계는 항상 원래 금액과 같다.
- 각자 몫은 비율대로 나눈 뒤 원 미만을 버린다.
- 남는 원은 1원씩 준다. 순서는 낸 사람이 참여자이면 낸 사람이 먼저이고, 그다음은 참여자 목록 순서다(`rules.REMAINDER_ORDER`).
- 예: 100원을 [가, 나, 다]가 나누고 나가 냈으면 가 33, 나 34, 다 33.

## 3. 날짜와 기간
- 날짜 형식은 `YYYY-MM-DD`, 월 형식은 `YYYY-MM`이다.
- 기간은 시작일과 끝일을 모두 포함한다(`dates.in_period`).
- 한 달은 1일부터 말일까지다(`dates.month_range`). 윤년 2월은 29일까지다.

## 4. 회원 기간
- 가입일부터 탈퇴일 당일까지 회원이다. 탈퇴 다음 날부터 지출 참여자가 될 수 없다(`queries.is_member_active`).
- 은행 출금처럼 참여자가 적혀 있지 않은 지출은 그날의 회원 전원이 참여자다.

## 5. 분류
- 분류가 없는 지출은 "미분류"로 센다(`rules.UNCATEGORIZED`).

## 6. 정산 확정
- 확정한 기간의 지출은 추가·수정·삭제·되살리기를 할 수 없다. 다른 날짜의 지출을 그 기간으로 옮기는 것도 안 된다(`queries.is_locked`).
- 잔액 합이 0이 아니면 확정하지 않는다.

## 6-1. 삭제
- 지출은 지우지 않고 삭제 표시만 한다. 삭제 표시된 지출은 합계·정산·보고서·내보내기에서 빠지고, 목록에서는 따로 요청할 때만 보인다.

## 6-2. 명부 검사
- 낸 사람과 참여자는 모두 명부에 있어야 하고, 그날 회원이어야 한다. 낸 사람이 참여자에 꼭 들어갈 필요는 없다.

## 7. 자료 파일
- 저장은 `Store.save()`만 쓴다. 임시 파일에 쓴 뒤 바꿔 끼우므로 저장 도중 멈춰도 파일이 깨지지 않는다.
- 저장할 때마다 `backup/` 에 직전 자료를 남기고 최근 10개를 둔다. 자료 파일이 깨졌으면 `Store.recover()`가 가장 최근 백업을 읽는다.
- 지출을 바꿀 때마다 `history` 에 바꾸기 전과 뒤를 남긴다.

## 8. 기능끼리의 경계
- 스켈레톤 코드에 있는 함수(공통 모듈·기능 파일)의 이름과 인자는 바꾸지 않는다. 새 함수와 새 자료 항목은 추가만 한다.
- `moim/features/` 의 파일은 서로 import 하지 않는다. 함께 써야 하는 계산은 `moim/common` 으로 옮긴다.
- 자동 검사(`tools/check_imports.py`)가 이 규칙을 확인한다.
- `moim/common` 을 바꾸는 병합 요청은 팀 전원이 내용을 알 수 있게 요청 설명에 무엇을 왜 바꿨는지 적는다.
