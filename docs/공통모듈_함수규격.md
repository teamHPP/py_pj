## 2. 공통 기준

모든 함수에 똑같이 적용한다. 각 절에서는 이 기준과 다른 점만 적는다.

### 금액

- 원 단위 `int`로 저장한다. `bool`은 금액으로 받지 않는다.
- 입력의 소수는 `money.to_won`으로 사사오입한다(2.5 → 3, 2.4 → 2).
- **지출 금액은 1원 이상**이어야 한다. 반면 `split`은 계산용 함수라서 0원도 받는다.

### 날짜와 기간

- 날짜 입력은 `str`, `datetime.date`, `datetime.datetime`을 받고, `dates.parse`와 같은 방식으로 해석한다. datetime은 날짜 부분만 쓴다(시간대 변환 없음).
- 저장하는 날짜는 `YYYY-MM-DD`, 월은 `YYYY-MM`이다.
- **기간은 시작일과 끝일을 모두 포함한다.** 예: 11월 30일 지출은 `11-01 ~ 11-30` 합계에 들어간다.
- 기간을 받는 함수에서 `start`나 `end`가 `None`이면 그쪽은 제한이 없다. 날짜 하나를 받는 함수(`on`, `value`)는 `None`을 받지 않는다.

### 지출 자료

- 삭제는 지우지 않고 `deleted=True` 표시만 한다. 삭제된 지출은 **합계·정산·보고서·내보내기에서 빠진다.**
- 지출에 `deleted`, `weights`, `category_fixed`, `recurring_id` 키가 없으면 각각 `False`, `None`, `False`, `None`으로 읽는다.
- 모르는 키는 지우지 않고 그대로 둔다.
- 집계할 때 지금 탈퇴한 사람이라고 해서 과거 지출에서 빼지 않는다.

### 결과의 모양

- 지출 목록을 돌려줄 때는 `(date, id)` 오름차순의 **깊은 복사본**을 돌려준다. 결과를 고쳐도 원본은 바뀌지 않는다.
- **결과 `dict`의 key 순서는 `expenses_in` 결과에서 처음 나온 순서**로 통일한다(04 · 06 · 11).
- 해당하는 자료가 없으면 오류가 아니라 `[]`, `{}`, `0`을 돌려준다.
- 잘못된 입력은 **이유를 한국어로 담은 `ValueError`**를 낸다. 파일을 다루다 생긴 오류는 `OSError` 계열을 그대로 올린다.

### 나머지 1원

- 비율대로 나눈 뒤 원 미만은 버린다. 남은 원은 **낸 사람이 참여자이면 낸 사람부터**, 그다음은 **참여자 목록 순서**로 1원씩 준다.
- 비율 분배에도 같은 순서를 쓴다.
- 예: 10,000원을 3명 [양정현, 신동훈, 이은경]이 나누고 양정현이 냈으면 → 양정현 3,334 · 신동훈 3,333 · 이은경 3,333.

### ⚠ 채점할 때 바뀌는 함수

공고문에 따르면 채점할 때 **규약 함수(금액, 날짜·기간, 회원 판정, 잠금 판정 등)는 교수님이 보관한 정상판으로 바꿔 끼운다.** 어느 함수가 바뀌는지 정확한 목록은 공개되지 않았다. 그래서 모든 공통 함수에 아래 규칙을 적용한다.

1. 함수를 **쓰는 쪽**은 "정상 입력에 대한 결과"에만 기댄다.
2. 이 문서에서 우리 팀이 더 정한 오류 검사(`ValueError`)에 기대지 않는다. 이름이 명부에 있는지, 날짜 형식이 맞는지, 시작 ≤ 끝인지는 **부르기 전에 각자 확인한다.**
3. 팀이 새로 더한 함수(A1~A4)는 바뀌지 않는다.

### 각 절의 읽는 법

| 항목 | 뜻 |
| --- | --- |
| **입력** | 받는 값의 자료형과 의미 |
| **반환** | 돌려주는 값의 모양 |
| **예시** | 3장의 예시 자료 S를 기준으로 한 입력과 결과 |
| **빈 자료** | 자료가 없을 때의 결과 |
| **오류** | `ValueError`를 내는 경우 |
| **먼저 필요한 것** | 구현하기 전에 병합되어 있어야 하는 다른 함수 (있을 때만) |
| **주의** | 쓰는 쪽이 알아야 할 점 (있을 때만) |

## 3. 예시 자료 S

**이 문서의 모든 예시는 아래 상태의 독립 복사본에서 시작한다.** 예시마다 따로 바꾼 부분은 그 예시에 적는다.

```python
P = ["양정현", "신동훈", "이은경"]

e = {
    "id": 1, "date": "2026-11-17", "payer": "양정현", "amount": 9000,
    "members": P, "category": "식비", "memo": "회의 후 저녁",
    "deleted": False, "weights": None, "recurring_id": None,
}

S.data = {
    "members": [
        {"name": "양정현", "joined": "2026-09-01", "left": None},
        {"name": "신동훈", "joined": "2026-09-01", "left": "2026-11-30"},
        {"name": "이은경", "joined": "2026-09-01", "left": None},
    ],
    "expenses": [e],
    "next_id": 2,
    "history": [], "locks": [], "transfers": [], "recurring": [], "payments": [],
}
```

- 신동훈은 **11월 30일에 탈퇴**한다. 탈퇴일 당일까지는 회원이고, 12월 1일부터는 회원이 아니다.
- `e`에는 `category_fixed` 키가 없다. 이 키는 기능 2가 분류를 직접 지정할 때만 생긴다(6장).

## 양정현 · 기능 1 지출 입력·관리

### 01. validate · 지출 한 건 검사

```python
validate(store, date, payer, amount, members, weights=None) -> tuple[str, int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/ledger.py` | 양정현 | 양정현(추가·수정), 진영서(가져오기 검사·미리 보기). 이은경·김정빈은 insert를 거쳐 사용 |

- **입력**
  - `date`: 날짜 / `payer`: 낸 사람 이름 `str` / `amount`: 금액(`str`, `int`, `float`, `Decimal`)
  - `members`: 비어 있지 않고 중복 없는 `list[str]` / `weights`: `dict[str, int]` 또는 `None`
  - 낸 사람과 참여자 **모두** 명부에 있고 그날 회원이어야 한다. 잠긴 날짜는 거부한다.
  - 비율은 직접 검사하지 않고 **`money.check_weights`(A1)를 호출한다.**
- **반환**: `(정규화한 "YYYY-MM-DD", 사사오입한 int 원)`. Store와 입력은 바꾸지 않는다.
- **예시**
  ```python
  validate(S, "2026-11-17", "양정현", "9,000", P)   # → ("2026-11-17", 9000)
  validate(S, "2026-11-17", "양정현", "2.5", P)     # → ("2026-11-17", 3)
  validate(S, "2026-11-17", "양정현", "inf", P)     # → ValueError
  ```
- **빈 자료**: 명부가 비어 있으면 "명부에 없는 사람" `ValueError`. 지출이 하나도 없는 것은 오류가 아니다.
- **오류**
  - 금액: 0 이하로 정규화되는 값, `bool`, `NaN`, 무한대, `1e400`처럼 너무 큰 수
  - 날짜: 없는 날짜, 잠긴 날짜
  - 사람: 명부에 없거나 그날 회원이 아닌 사람, 빈 참여자, 중복 참여자
  - 비율: `check_weights`가 거부하는 경우
  - 예: `members=[]` → `ValueError("참여자가 비어 있습니다")`
- **주의: 금액 변환 예외**
  - 지금 `money.to_won`은 `quantize()`가 try 블록 밖에 있다. 그래서 `inf`·`-inf`·`1e400`을 넣으면 `ValueError`가 아닌 `decimal.InvalidOperation`이 나고, `nan`은 영어 메시지의 `ValueError`가 난다(2026-11-18 실행 확인).
  - 그래서 validate는 `to_won` 호출을 `try/except (ValueError, ArithmeticError)`로 감싸 `ValueError("금액 형식이 잘못되었습니다: …")`로 바꾼다.
  - `to_won`은 채점 때 정상판으로 바뀔 수 있으므로, validate가 **스스로** 이 계약을 지킨다.
  - `to_won` 자체의 수정은 별도 공통 모듈 PR로 올린다.

### 02. insert · 검사 후 지출 저장

```python
insert(store, date, payer, amount, members, memo="", weights=None, category=None,
       recurring_id=None, action="add") -> dict
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/ledger.py` | 양정현 | 양정현(추가·파일 입력), 이은경(반복 지출), 김정빈(은행 출금), 진영서(CSV 가져오기·합치기) |

- **입력**
  - 앞의 여섯 인자는 `validate`와 같은 기준으로 검사한다.
  - `memo`: `str` / `category`: `str` 또는 `None` / `recurring_id`: 양의 `int` 또는 `None`
  - `action`: `INSERT_ACTIONS`(A2)에 있는 값만 받는다.
  - 목록과 비율은 독립 복사해서 저장한다.
- **반환**: 저장한 새 지출 `dict`의 독립 복사본.
- **처리 순서** (실패하면 Store가 바뀌지 않도록 하기 위한 순서)
  1. `validate`와 memo·category·recurring_id·action·next_id 검사를 **모두** 끝낸다.
  2. 다 통과한 뒤에만 `store.new_id()`를 부른다. `new_id()`는 부르는 즉시 `next_id`를 올리기 때문이다.
  3. 지출 dict를 만들어 `expenses`에 넣고 `Store.record(action, id, None, 새 지출)`(A3)을 부른다.

  2단계부터는 예외가 날 수 없는 메모리 작업만 둔다. **디스크 저장은 하지 않는다.** 저장은 명령 쪽에서 `Store.save()`로 한다.
- **만드는 키**: `id, date, payer, amount, members, memo, weights, category, deleted, recurring_id`
  - `category_fixed`는 기능 2의 필드라서 **insert는 만들지 않는다.**
  - 중복 의심은 insert가 거부할 이유가 아니다(18 duplicates 참고).
- **예시**
  ```python
  insert(S, "2026-11-18", "양정현", 9000, P, category="식비")
  # → {"id": 2, "date": "2026-11-18", "payer": "양정현", "amount": 9000, "members": P,
  #    "memo": "", "weights": None, "category": "식비", "deleted": False, "recurring_id": None}
  # S.data["next_id"] → 3
  # S.data["history"][-1]
  # → {"at": "2026-11-18T14:05:00", "action": "add", "id": 2, "before": None, "after": {위 지출과 같은 내용}}

  insert(S, "2026-11-18", "양정현", 9000, P, action="imported")
  # → ValueError (목록에 없는 action), S.data["next_id"]는 2 그대로
  ```
- **빈 자료**: 지출이 하나도 없고 `next_id=1`이면 1번부터 넣는다.
- **오류**: validate의 오류, 잘못된 memo·category·recurring_id·next_id, `INSERT_ACTIONS`에 없는 action. **실패하면 expenses·next_id·history를 포함해 Store 전체가 부르기 전과 같다.**
- **먼저 필요한 것**: 01 validate, A2 INSERT_ACTIONS, A3 Store.record

### 07. table · 글자 표

```python
table(headers, rows, total=None, numeric=None) -> str
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/textfmt.py` | 성수빈 | 성수빈(보고서), 양정현(목록), 이은경(정산), 김정빈(예산) |

- **입력**
  - `headers`: 비어 있지 않은 `list[str]`
  - `rows`: headers와 열 수가 같은 `list[list[str | int]]`
  - `total`: 열 수가 같은 합계 행 또는 `None`
  - `numeric`: 오른쪽 정렬할 열 번호(0부터)의 `set` 또는 `None`
- **반환 규칙**
  - `int` 셀에는 천 단위 쉼표를 붙인다. 쉼표가 없어야 하는 번호 같은 열은 `str()`로 넘긴다.
  - `numeric` 열은 오른쪽 정렬, 나머지는 왼쪽 정렬, 제목은 항상 왼쪽 정렬이다.
  - 열 폭은 `textfmt.width` 기준(한글 2칸)으로 headers·rows·total 중 가장 넓은 값이다.
  - 셀 사이는 공백 두 칸, 줄 사이는 `\n`이다. 줄 끝 공백과 마지막 개행은 없다.
  - 구분선(열 폭만큼 `-`)은 **첫 자료 행 앞**과 **total 앞**에 둔다. rows가 없으면 자료 행 앞 구분선도 없다.
  - 출력하지 않고 문자열만 돌려준다.
- **예시**
  ```python
  table(["A"], [["B"]])
  # → "A\n-\nB"

  table(["금액"], [[9000]], total=[9000], numeric={0})
  # → "금액\n-----\n9,000\n-----\n9,000"

  table(["이름", "금액"], [["양정현", 9000]], total=["합계", 9000], numeric={1})
  # →
  # 이름    금액
  # ------  -----
  # 양정현  9,000
  # ------  -----
  # 합계    9,000
  ```
- **빈 자료**: `table(["금액"], [], numeric={0})` → `"금액"`, `table(["A"], [], total=["T"])` → `"A\n-\nT"`
- **오류**: 빈 headers, `str`이 아닌 제목, 열 수 불일치, 범위 밖·`bool`·정수가 아닌 열 번호, `bool`·`float`·`None` 셀
  - 예: `table(["금액"], [[9000, 1]])` → `ValueError("행의 열 수가 제목과 다릅니다")`
- **주의**: 증감률처럼 `float`나 `None`인 값은 쓰는 쪽에서 문자열로 바꿔 넘긴다.

### 08. bar_chart · 글자 막대그래프


  - 예: `bar_chart({"식비": -1})` → `ValueError("막대 값은 0 이상의 정수여야 합니다")`

### 09. split · 금액 나누기 (비율 분배 추가)

```python
split(amount, members, payer=None, weights=None) -> dict[str, int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/money.py` | 이은경 | 이은경(부담액·정산), 김정빈(회비 차감) |

- 지금 있는 균등 분배는 그대로 두고, **비율 분배 부분만** 채운다.
- **입력**
  - `amount`: 0 이상의 `int` (`bool` 제외) / `members`: 비어 있지 않고 중복 없는 `list[str]`
  - `payer`: 이름 `str` 또는 `None`. 참여자가 아니어도 된다.
  - `weights`: **`check_weights(members, weights)`(A1)로 검사하고 정규화한다.** split 안에 비율 기준을 따로 적지 않는다.
- **반환**: 참여자 순서의 `{이름: 부담액}`. 비율대로 나눠 원 미만을 버리고, 남은 원은 2장의 나머지 순서로 준다. 합계는 항상 `amount`다.
- **예시**
  ```python
  split(100, P, payer="신동훈")                    # → {"양정현": 33, "신동훈": 34, "이은경": 33}
  split(10000, P, payer="양정현")                  # → {"양정현": 3334, "신동훈": 3333, "이은경": 3333}
  split(10001, P, "양정현", {"양정현": 2})         # → {"양정현": 5001, "신동훈": 2500, "이은경": 2500}
  split(0, P)                                     # → {"양정현": 0, "신동훈": 0, "이은경": 0}
  ```
- **빈 자료**: 빈 참여자는 `ValueError`. `amount=0`은 모두 0을 돌려준다(0원 지출 금지는 validate가 맡는다).
- **오류**: 음수·`bool`·정수가 아닌 금액, 빈·중복 참여자, 잘못된 payer 자료형, `check_weights`가 거부하는 비율
- **먼저 필요한 것**: A1 check_weights

  1. `backups()`를 **최신부터** 보며 JSON과 자료 모양이 정상인 첫 백업을 고른다. 깨진 백업은 건너뛴다.
  2. 깨진 주 자료 파일을 옆에 `<자료파일명>.broken.<YYYYMMDD_HHMMSS>`로 남긴다.
  3. 같은 폴더의 임시 파일에 백업 내용을 쓰고, 닫은 뒤 `os.replace`로 주 자료 파일과 바꾼다.
  4. 성공한 뒤에만 `self.data`와 `self.recovered_from`(고른 백업의 절대 경로)을 바꾼다.
  - 새로 생긴 최상위 항목이 백업에 없으면 기본값으로 채우고, 모르는 키는 그대로 둔다.
  - 깨진 주 파일을 자동 백업 목록에 넣지 않는다.
- **반환**: 같은 Store 객체 `self`
- **예시**
  ```python
  # b2는 깨졌고 b1은 정상, 주 파일도 깨진 상태
  R = S.recover()
  R is S                # → True
  S.recovered_from      # → b1
  # 주 파일은 b1 내용, 깨진 원본은 data.json.broken.… 로 남음
  ```
- **빈 자료**: 백업이 없거나 모두 깨졌으면 `ValueError("복구할 정상 백업이 없습니다")`. 이때 주 파일·`self.data`·`recovered_from`은 바꾸지 않는다.
- **오류**: 잘못된 경로 자료형은 `ValueError`, 파일 읽기·쓰기 오류는 `OSError`. 어떤 경우에도 원본을 잃거나 메모리만 먼저 바꾸지 않는다.
- **먼저 필요한 것**: 13 Store.backups


- **반환**: 날짜·낸 사람·금액이 같고 **삭제되지 않은** 지출 번호 목록, 오름차순. `exclude_id`는 뺀다.


- **부르는 순서 (양정현과 합의)**: 지출을 넣거나 고치는 쪽은 다음 순서로 부른다.
  1. `validate`
  2. 1의 결과 `(날짜, 원 금액)`으로 `duplicates`
  3. `insert`

  그래서 `-5`원 같은 입력에는 항상 **validate의 오류 문구**가 나간다. duplicates의 입력 검사는 잘못 직접 불렀을 때를 막는 용도다. insert 안에서 validate가 한 번 더 불리지만 자료를 바꾸지 않으므로 결과는 같다.

### 22. read_csv_rows · CSV 읽기와 열 이름 연결

```python
read_csv_rows(path, mapping=None, encoding=None) -> tuple[str, list[tuple[int, dict]]]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/csvio.py` | 진영서 | 진영서(CSV 가져오기·미리 보기), 김정빈(은행 거래내역 가져오기) |

- **입력**
  - `mapping`: `{파일 열 이름: 내부 필드 이름}` 또는 `None`
    - 한 필드에 후보 이름을 여러 개 둘 수 있다. 예: `{"날짜": "date", "거래일자": "date", "금액": "amount"}`
    - **파일에 없는 mapping 키는 무시한다.**
    - 실제 파일 열 두 개 이상이 같은 필드 이름이 될 때만 오류다. mapping하지 않은 열의 이름이 다른 열의 mapping 결과와 겹치는 경우도 포함한다.
    - mapping하지 않은 열은 이름을 그대로 둔다. 헤더는 앞뒤 공백을 지운 뒤 mapping한다.
  - `encoding`: `"utf-8"`, `"utf-8-sig"`, `"cp949"` 또는 `None`
    - `None`이면 `detect_encoding`을 쓴다.
    - **UTF-8 계열은 넘긴 값과 상관없이 항상 `"utf-8-sig"`로 읽고 `"utf-8-sig"`를 돌려준다.** BOM이 있어도 첫 열 이름이 깨지지 않게 하기 위해서다.
- **반환**: `(실제 쓴 인코딩, [(레코드가 시작된 줄 번호, 행 dict)])`
  - 값은 바꾸지 않은 문자열 그대로다(공백도 지우지 않음).
  - 열 수가 맞지 않는 행도 그대로 돌려준다(`csv.DictReader` 관례). 짧은 행의 빈 칸은 `None`, 긴 행의 넘치는 값은 `None` key의 `list[str]`로 들어간다.
- **예시**
  ```python
  # 파일(UTF-8): 거래일자,금액\n2026-11-17,"9,000"\n
  read_csv_rows("a.csv", {"거래일자": "date", "금액": "amount"})
  # → ("utf-8-sig", [(2, {"date": "2026-11-17", "amount": "9,000"})])

  read_csv_rows("a.csv", {"날짜": "date", "거래일자": "date", "금액": "amount"})
  # → 위와 같음 ("날짜" 열은 파일에 없으므로 무시)

  read_csv_rows("a.csv", {"거래일자": "date", "금액": "amount"}, encoding="utf-8")
  # → 반환 인코딩은 "utf-8-sig"

  # 파일에 "날짜"와 "거래일자" 열이 둘 다 있고 둘 다 date로 mapping → ValueError
  ```
  - 따옴표 안의 값이 여러 줄이어도 줄 번호는 그 레코드가 **시작된** 줄이다.
- **빈 자료**: 빈 파일이나 헤더만 있는 파일은 `(인코딩, [])`. 빈 줄은 건너뛰지만 뒤 줄 번호는 실제 번호를 유지한다.
- **오류**
  - `ValueError`: 빈 헤더나 중복 헤더, mapping 뒤 열끼리 필드 이름 충돌, 잘못된 mapping 자료형(dict가 아님, key·값이 빈 문자열이거나 `str`이 아님), 잘못된 encoding, 읽을 수 없는 파일, 행 경계를 복구할 수 없는 CSV 문법
  - `OSError`: 파일 접근 오류
- **주의 (부르는 쪽이 할 일)**
  - 필수 열(date, amount 등)이 있는지는 부르는 쪽이 먼저 확인한다.
  - `None` key나 `None` 값이 있는 행은 열 수 오류로 보고, 그 줄만 errors에 모은다.
  - 금액·날짜는 각 공통 함수(`money.to_won`, `dates.parse`)로 바꾼다.
- **먼저 필요한 것**: 21 detect_encoding

- 값을 늘릴 때는 이 상수에 더하는 **공통 모듈 PR**로만 한다.

### A3. Store.record · 이력 남기기

```python
store.record(action, eid, before, after) -> None
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/store.py` | 양정현 | 02 insert, 지출을 바꾸는 모든 함수 |

- `store.data["history"]` 끝에 이력 하나를 붙인다. 메모리만 바꾸고 디스크에는 저장하지 않는다.
- **이력 한 건의 모양**
  ```python
  {"at": "2026-11-18T14:05:00",   # 기록한 시각
   "action": "edit",              # 아래 표의 값
   "id": 1,                       # 지출 번호
   "before": {...} or None,       # 바꾸기 전 지출 (깊은 복사)
   "after":  {...} or None}       # 바꾼 뒤 지출 (깊은 복사)
  ```
- **action 값**

  | action | 언제 | before | after | 담당 |
  | --- | --- | --- | --- | --- |
  | `INSERT_ACTIONS`의 값 | 새 지출 추가 | **`None`** | 새 지출 | insert |
  | `"edit"` | 지출 수정 | 수정 전 | 수정 후 | 양정현 |
  | `"delete"` | 삭제 표시 | 삭제 전 | `deleted=True`인 지출 | 양정현 |
  | `"restore"` | 되살리기 | 되살리기 전 | `deleted=False`인 지출 | 양정현 |
  | `"undo"` | 직전 수정 되돌리기 | 되돌리기 전 | 되돌린 후 | 양정현 |
  | `"exclude"` | 특정 지출에서 특정 사람 빼기 | 빼기 전 | 뺀 후 | 이은경 |

  - 새 지출의 `before`는 `{}`가 아니라 **`None`**이다. `{}`는 "키가 하나도 없던 지출"과 헷갈리기 때문이다.
  - 삭제는 지우는 게 아니라 표시만 하므로 `after`도 지출 dict다.
  - `undo_last_edit`는 `action == "edit"`인 이력만 찾는다. insert 이력은 다른 값을 쓰므로 섞이지 않는다.

### A4. Store.save · 안전 저장 (내용 바꾸기)

```python
store.save() -> None
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/store.py` | 이은경 (자료 파일 손상 대응) | 김정빈(통합 실행이 명령 뒤에 호출) |

- 이름과 인자는 그대로 두고 내용만 바꾼다.
- **동작 순서**
  1. 주 자료 파일이 있으면 `backup_dir`에 `<자료파일명>.<YYYYMMDD_HHMMSS_ffffff>.<8자리 16진수>.bak`로 복사한다.

  3. 백업이 `keep`(기본 10)개를 넘으면 가장 오래된 것부터 지운다.
- **반환**: `None`. 실패하면 예외를 그대로 올린다.

### store.py의 EMPTY에 더하는 최상위 항목

공고문에 따라 **각 항목은 그 기능 담당자가 추가**한다. `store.py`의 EMPTY는 충돌이 잦은 곳이므로 **한 PR에 한 항목만** 더한다.

| 항목 | 기본값 | 한 건의 모양 | 담당 |
| --- | --- | --- | --- |
| `history` | `[]` | A3의 이력 dict | 양정현 |
| `locks` | `[]` | `{"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"}` | 이은경 |
| `transfers` | `[]` | `{"date": "YYYY-MM-DD", "from": 보낸 사람, "to": 받은 사람, "amount": int}` | 이은경 |
| `recurring` | `[]` | `{"id": int, "day": 1~31, "payer": str, "amount": int, "members": list[str], "memo": str, "weights": dict 또는 None, "start_month": "YYYY-MM", "last_month": "YYYY-MM" 또는 None}` | 이은경 |
| `payments` | `[]` | `{"date": "YYYY-MM-DD", "member": str, "amount": int, "memo": str}` | 김정빈 |

- `recurring`
  - `id`는 기존 반복 지출 id의 최댓값 + 1이다.
  - `last_month`는 마지막으로 지출을 만든 달이다.
  - 그달에 없는 날(31일 등)은 말일로 만든다.
- 담당자가 필요한 키를 더 붙일 수 있다(추가만 함). 예: 은행 가져오기의 중복 방지 표시
- 옛 자료 파일에 항목이 없으면 `Store.load`가 기본값으로 채운다. 지금 `_check_shape`가 이미 그렇게 한다.

### 지출 한 건에 더하는 필드

이 필드들은 최상위 항목으로 옮기지 않는다.

| 필드 | 기본값(없을 때) | 누가 쓰는가 | 담당 |

## 9. 기능끼리 연결할 때 지킬 것

- **Store 메서드 반환값**: `Store.load()`는 `self`를 돌려준다. `Store.save()`는 `None`을 돌려주고 실패하면 예외를 올린다. 주 자료 저장은 통합 실행(김정빈)이 명령 뒤에 한다.
- **경로 전달**: 진영서가 설정에서 자료·백업·로그 경로를 준비하고, 김정빈이 Store와 로거에 넘긴다. `get_logger()`는 `logging.Logger`를 돌려준다.
- **명령의 `run()` 반환값**: 자료를 바꿨으면 `True`, 조회·미리 보기면 `False`. 출력은 명령 계층에서 한다.
- **자료 보존**: 저장·백업·복구할 때 `history`, `locks`, `transfers`, `recurring`, `payments`와 모르는 키를 모두 그대로 둔다.
- **두 종류의 백업**: 진영서의 "전체 자료 백업·복원"(사용자가 경로를 정함)과 A4의 자동 백업은 다른 기능이다. 전체 복원을 만들 때는 회원·입금·이력·잠금까지 넣을지 범위를 따로 적는다.
- **기능 파일끼리 import 금지**: 둘 이상의 기능이 쓰는 계산은 `moim/common`에 둔다(`tools/check_imports.py`가 검사).
- **규격 변경 절차**: 이 문서를 바꿀 때는 그 함수 담당자와 쓰는 사람에게 알리고, 10장에 버전과 날짜를 적는다. 규약(`docs/규약.md`)의 값을 바꾸려면 교수의 승인을 먼저 받는다.
