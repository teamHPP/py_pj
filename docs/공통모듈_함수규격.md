## 1. 공통 기준

모든 함수에 똑같이 적용한다. 각 절에서는 이 기준과 다른 점만 적는다.

### 금액

- 원 단위 `int`로 저장한다. `bool`은 금액으로 받지 않는다.
- 입력의 소수는 `money.to_won`으로 사사오입한다(2.5 → 3, 2.4 → 2).
- **지출 금액은 1원 이상**이어야 한다.

### 날짜와 기간

- 날짜 입력은 `str`, `datetime.date`, `datetime.datetime`을 받고, `dates.parse`와 같은 방식으로 해석한다. datetime은 날짜 부분만 쓴다(시간대 변환 없음).
- 저장하는 날짜는 `YYYY-MM-DD`, 월은 `YYYY-MM`이다.
- **기간은 시작일과 끝일을 모두 포함한다.** 예: 11월 30일 지출은 `11-01 ~ 11-30` 합계에 들어간다.

### 지출 자료

- 삭제는 지우지 않고 `deleted=True` 표시만 한다. 삭제된 지출은 **합계·정산·보고서·내보내기에서 빠진다.**
- 지출에 `deleted`, `weights`, `category_fixed`, `recurring_id` 키가 없으면 각각 `False`, `None`, `False`, `None`으로 읽는다.
- 모르는 키는 지우지 않고 그대로 둔다.

### 결과의 모양

- 지출 목록을 돌려줄 때는 `(date, id)` 오름차순의 **깊은 복사본**을 돌려준다. 결과를 고쳐도 원본은 바뀌지 않는다.
- 해당하는 자료가 없으면 오류가 아니라 `[]`, `{}`, `0`을 돌려준다.
- 잘못된 입력은 **이유를 한국어로 담은 `ValueError`**를 낸다. 파일을 다루다 생긴 오류는 `OSError` 계열을 그대로 올린다.

### ⚠ 채점할 때 바뀌는 함수

공고문에 따르면 채점할 때 **규약 함수(금액, 날짜·기간, 회원 판정, 잠금 판정 등)는 교수님이 보관한 정상판으로 바꿔 끼운다.** 어느 함수가 바뀌는지 정확한 목록은 공개되지 않았다. 그래서 모든 공통 함수에 아래 규칙을 적용한다.

1. 함수를 **쓰는 쪽**은 "정상 입력에 대한 결과"에만 기댄다.
2. 이 문서에서 우리 팀이 더 정한 오류 검사(`ValueError`)에 기대지 않는다. 부르기 전에 각자 확인한다.
3. 팀이 새로 더한 함수(A1~A4)는 바뀌지 않는다.

## 2. 예시 자료 S

**이 문서의 모든 예시는 아래 상태의 독립 복사본에서 시작한다.** 예시마다 따로 바꾼 부분은 그 예시에 적는다.

```python
P = ["양정현", "신동훈", "이은경"]

e = {
    "id": 1, "date": "2026-11-17", "payer": "양정현", "amount": 9000,
    "members": P, "category": "식비", "memo": "회의 후 저녁",
    "deleted": False, "weights": None, "recurring_id": None,
}

S.data = {
    "members": [
        {"name": "양정현", "joined": "2026-09-01", "left": None},
        {"name": "신동훈", "joined": "2026-09-01", "left": "2026-11-30"},
        {"name": "이은경", "joined": "2026-09-01", "left": None},
    ],
    "expenses": [e],
    "next_id": 2,
    "history": [], "locks": [], "transfers": [], "recurring": [], "payments": [],
}
```

- `e`에는 `category_fixed` 키가 없다. 이 키는 기능 2가 분류를 직접 지정할 때만 생긴다.

## 양정현 · 기능 1 지출 입력·관리

### 01. validate · 지출 한 건 검사

```python
validate(store, date, payer, amount, members, weights=None) -> tuple[str, int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/ledger.py` | 양정현 | 양정현(추가·수정), 진영서(가져오기 검사·미리 보기). 이은경·김정빈은 insert를 거쳐 사용 |

- **입력**
  - `date`: 날짜 / `payer`: 낸 사람 이름 `str` / `amount`: 금액(`str`, `int`, `float`, `Decimal`)
  - `members`: 비어 있지 않고 중복 없는 `list[str]` / `weights`: `dict[str, int]` 또는 `None`
  - 낸 사람과 참여자 **모두** 명부에 있고 그날 회원이어야 한다. 잠긴 날짜는 거부한다.
  - 비율은 직접 검사하지 않고 **`money.check_weights`(A1)를 호출한다.**
- **반환**: `(정규화한 "YYYY-MM-DD", 사사오입한 int 원)`. Store와 입력은 바꾸지 않는다.
- **예시**
  ```python
  validate(S, "2026-11-17", "양정현", "9,000", P)   # → ("2026-11-17", 9000)
  validate(S, "2026-11-17", "양정현", "2.5", P)     # → ("2026-11-17", 3)
  validate(S, "2026-11-17", "양정현", "inf", P)     # → ValueError
  ```
- **빈 자료**: 명부가 비어 있으면 "명부에 없는 사람" `ValueError`. 지출이 하나도 없는 것은 오류가 아니다.
- **오류**
  - 금액: 0 이하로 정규화되는 값, `bool`, `NaN`, 무한대, `1e400`처럼 너무 큰 수
  - 날짜: 없는 날짜, 잠긴 날짜
  - 사람: 명부에 없거나 그날 회원이 아닌 사람, 빈 참여자, 중복 참여자
  - 비율: `check_weights`가 거부하는 경우
  - 예: `members=[]` → `ValueError("참여자가 비어 있습니다")`
- **주의: 금액 변환 예외**
  - 지금 `money.to_won`은 `quantize()`가 try 블록 밖에 있다. 그래서 `inf`·`-inf`·`1e400`을 넣으면 `ValueError`가 아닌 `decimal.InvalidOperation`이 나고, `nan`은 영어 메시지의 `ValueError`가 난다(2026-11-18 실행 확인).
  - 그래서 validate는 `to_won` 호출을 `try/except (ValueError, ArithmeticError)`로 감싸 `ValueError("금액 형식이 잘못되었습니다: …")`로 바꾼다.
  - `to_won`은 채점 때 정상판으로 바뀔 수 있으므로, validate가 **스스로** 이 계약을 지킨다. `to_won` 자체의 수정은 별도 공통 모듈 PR로 올린다.

### 02. insert · 검사 후 지출 저장

```python
insert(store, date, payer, amount, members, memo="", weights=None, category=None,
       recurring_id=None, action="add") -> dict
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/ledger.py` | 양정현 | 양정현(추가·파일 입력), 이은경(반복 지출), 김정빈(은행 출금), 진영서(CSV 가져오기·합치기) |

- **입력**
  - 앞의 여섯 인자는 `validate`와 같은 기준으로 검사한다.
  - `memo`: `str` / `category`: `str` 또는 `None` / `recurring_id`: 양의 `int` 또는 `None`
  - `action`: `INSERT_ACTIONS`(A2)에 있는 값만 받는다.
  - 목록과 비율은 독립 복사해서 저장한다.
- **반환**: 저장한 새 지출 `dict`의 독립 복사본.
- **처리 순서** (실패하면 Store가 바뀌지 않도록 하기 위한 순서)
  1. `validate`와 memo·category·recurring_id·action·next_id 검사를 **모두** 끝낸다.
  2. 다 통과한 뒤에만 `store.new_id()`를 부른다. `new_id()`는 부르는 즉시 `next_id`를 올리기 때문이다.
  3. 지출 dict를 만들어 `expenses`에 넣고 `Store.record(action, id, None, 새 지출)`(A3)을 부른다.

  2단계부터는 예외가 날 수 없는 메모리 작업만 둔다. **디스크 저장은 하지 않는다.** 저장은 명령 쪽에서 `Store.save()`로 한다.
- **만드는 키**: `id, date, payer, amount, members, memo, weights, category, deleted, recurring_id`
  - `category_fixed`는 기능 2의 필드라서 **insert는 만들지 않는다.**
  - 중복 의심은 insert가 거부할 이유가 아니다.
- **예시**
  ```python
  insert(S, "2026-11-18", "양정현", 9000, P, category="식비")
  # → {"id": 2, "date": "2026-11-18", "payer": "양정현", "amount": 9000, "members": P,
  #    "memo": "", "weights": None, "category": "식비", "deleted": False, "recurring_id": None}
  # S.data["next_id"] → 3
  # S.data["history"][-1]
  # → {"at": "2026-11-18T14:05:00", "action": "add", "id": 2, "before": None, "after": {위 지출과 같은 내용}}

  insert(S, "2026-11-18", "양정현", 9000, P, action="imported")
  # → ValueError (목록에 없는 action), S.data["next_id"]는 2 그대로
  ```
- **빈 자료**: 지출이 하나도 없고 `next_id=1`이면 1번부터 넣는다.
- **오류**: validate의 오류, 잘못된 memo·category·recurring_id·next_id, `INSERT_ACTIONS`에 없는 action. **실패하면 expenses·next_id·history를 포함해 Store 전체가 부르기 전과 같다.**
- **먼저 필요한 것**: 01 validate, A2 INSERT_ACTIONS, A3 Store.record (이 문서에 함께 올림)

### 09. split · 금액 나누기 (비율 분배 추가)

```python
split(amount, members, payer=None, weights=None) -> dict[str, int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/money.py` | 이은경 | 이은경(부담액·정산), 김정빈(회비 차감) |

- 지금 있는 균등 분배는 그대로 두고, **비율 분배 부분만** 채운다.
- **입력**
  - `amount`: 0 이상의 `int` (`bool` 제외) / `members`: 비어 있지 않고 중복 없는 `list[str]`
  - `payer`: 이름 `str` 또는 `None`. 참여자가 아니어도 된다.
  - `weights`: **`check_weights(members, weights)`(A1)로 검사하고 정규화한다.** split 안에 비율 기준을 따로 적지 않는다.
- **반환**: 참여자 순서의 `{이름: 부담액}`. 합계는 항상 `amount`다.
  1. 비율대로 나눠 원 미만을 버린다.
  2. 남은 원은 **낸 사람이 참여자이면 낸 사람부터**, 그다음은 **참여자 목록 순서**로 1원씩 준다.
- **예시**
  ```python
  split(100, P, payer="신동훈")              # → {"양정현": 33, "신동훈": 34, "이은경": 33}
  split(10000, P, payer="양정현")            # → {"양정현": 3334, "신동훈": 3333, "이은경": 3333}
  split(10001, P, "양정현", {"양정현": 2})   # → {"양정현": 5001, "신동훈": 2500, "이은경": 2500}
  split(0, P)                               # → {"양정현": 0, "신동훈": 0, "이은경": 0}
  ```
- **빈 자료**: 빈 참여자는 `ValueError`. `amount=0`은 모두 0을 돌려준다(0원 지출 금지는 validate가 맡는다).
- **오류**: 음수·`bool`·정수가 아닌 금액, 빈·중복 참여자, 잘못된 payer 자료형, `check_weights`가 거부하는 비율
- **먼저 필요한 것**: A1 check_weights

### 10. expense_shares · 지출 한 건의 사람별 부담액

```python
expense_shares(e) -> dict[str, int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/queries.py` | 이은경 | 이은경, 김정빈 |

- **입력**: 지출 `dict` 하나. `amount`(1 이상 `int`), `members`, `payer`, `weights`(없으면 `None`)를 쓴다.
- **반환**: `money.split(amount, members, payer, weights)`의 결과 그대로. 지출 원본은 바꾸지 않는다.
- **예시**
  ```python
  expense_shares(e)   # → {"양정현": 3000, "신동훈": 3000, "이은경": 3000}
  ```
- **빈 자료**: 한 건을 받는 함수라 빈 지출이나 빈 참여자는 `ValueError`다(`{}`를 돌려주지 않음).
- **오류**: dict가 아님, 필수 키 누락, 잘못된 금액·참여자·낸 사람·비율
- **먼저 필요한 것**: 09 split
- **주의**: 명부·재적 여부는 다시 검사하지 않고 저장된 지출을 그대로 계산한다. 삭제된 지출을 빼는 일은 기간 조회(05)가 한다.

### 11. member_shares · 기간 안의 사람별 부담액

```python
member_shares(store, start, end) -> dict[str, int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/queries.py` | 이은경 | 이은경(정산의 부담할 돈 owed), 김정빈(회비·부담액) |

- **입력**: 기간 `start`, `end`. `None`이면 그쪽은 제한이 없다.
- **반환**: `{참여자: 기간 안 부담액 합}`. `expenses_in(store, start, end)`로 고른 지출마다 `expense_shares`를 더한다.
  - 계산상 0원인 참여자도 넣는다. 지출에 참여하지 않은 회원은 넣지 않는다.
  - key 순서는 `expenses_in` 결과에서 처음 나온 순서다.
  - 지금 탈퇴한 사람이라고 해서 과거 부담액에서 빼지 않는다.
- **예시**
  ```python
  member_shares(S, "2026-11-01", "2026-11-30")   # → {"양정현": 3000, "신동훈": 3000, "이은경": 3000}
  member_shares(S, "2026-12-01", "2026-12-31")   # → {}
  ```
- **빈 자료**: `{}`
- **오류**: `expenses_in`과 `expense_shares`가 낸 `ValueError`를 그대로 올린다.
- **먼저 필요한 것**: 05 expenses_in, 10 expense_shares

### 12. is_locked · 확정된 날짜인가

```python
is_locked(store, on) -> bool
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/queries.py` | 이은경 | 양정현(validate·수정·삭제), 진영서(가져오기), (insert를 거쳐) 김정빈 |

- **입력**: 날짜 `on`. `store.data["locks"]`는 `[{"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"}]` 모양이다(아래 자료 항목 표).
- **반환**: `on`이 확정 기간 하나라도 안에 있으면(양끝 포함) `True`
- **예시**
  ```python
  is_locked(S, "2026-11-17")   # → False
  # S의 locks에 {"start": "2026-11-01", "end": "2026-11-30"}을 넣으면
  is_locked(S, "2026-11-30")   # → True   (끝일 포함)
  is_locked(S, "2026-12-01")   # → False
  ```
- **빈 자료**: `locks`가 없거나 비어 있으면 `False`. 이때도 `on` 날짜는 검사한다.
- **오류**: `on`이 `None`·빈 값·잘못된 날짜, locks의 자료형 오류나 start > end
- **주의**
  - 조회만 한다. 실제로 막는 일은 지출을 바꾸는 쪽(validate, 수정·삭제·되살리기)이 이 결과를 보고 한다.
  - 다른 날짜의 지출을 잠긴 기간으로 **옮기는 것**도 막아야 하므로, 수정할 때는 바꾸기 전 날짜와 바꾼 뒤 날짜를 둘 다 검사한다.

### 14. Store.recover · 마지막 정상 백업으로 복구

```python
store.recover() -> Store   # self
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/store.py` | 이은경 | 김정빈(자료 파일이 깨졌을 때 CLI에서 호출·안내) |

- **동작 순서**
  1. `backups()`를 **최신부터** 보며 JSON과 자료 모양이 정상인 첫 백업을 고른다. 깨진 백업은 건너뛴다.
  2. 깨진 주 자료 파일을 옆에 `<자료파일명>.broken.<YYYYMMDD_HHMMSS>`로 남긴다.
  3. 같은 폴더의 임시 파일에 백업 내용을 쓰고, 닫은 뒤 `os.replace`로 주 자료 파일과 바꾼다.
  4. 성공한 뒤에만 `self.data`와 `self.recovered_from`(고른 백업의 절대 경로)을 바꾼다.
  - 백업에 없는 새 최상위 항목은 기본값으로 채우고, 모르는 키는 그대로 둔다.
- **반환**: 같은 Store 객체 `self`
- **예시**
  ```python
  # b2는 깨졌고 b1은 정상, 주 파일도 깨진 상태
  R = S.recover()
  R is S              # → True
  S.recovered_from    # → b1   (주 파일은 b1 내용, 깨진 원본은 data.json.broken.… 로 남음)
  ```
- **빈 자료**: 백업이 없거나 모두 깨졌으면 `ValueError("복구할 정상 백업이 없습니다")`. 이때 주 파일·`self.data`·`recovered_from`은 바꾸지 않는다.
- **오류**: 잘못된 경로 자료형은 `ValueError`, 파일 읽기·쓰기 오류는 `OSError`. 어떤 경우에도 원본을 잃거나 메모리만 먼저 바꾸지 않는다.
- **먼저 필요한 것**: 13 Store.backups

### 기능 4가 더하는 자료 항목

`store.py`의 `EMPTY`에 더하는 최상위 항목이다. `EMPTY`는 충돌이 잦은 곳이므로 **코드로 올릴 때는 한 PR에 한 항목씩** 더한다.

| 항목 | 기본값 | 한 건의 모양 |
| --- | --- | --- |
| `locks` | `[]` | `{"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"}` |
| `transfers` | `[]` | `{"date": "YYYY-MM-DD", "from": 보낸 사람, "to": 받은 사람, "amount": int}` |
| `recurring` | `[]` | `{"id": int, "day": 1~31, "payer": str, "amount": int, "members": list[str], "memo": str, "weights": dict 또는 None, "start_month": "YYYY-MM", "last_month": "YYYY-MM" 또는 None}` |

- `recurring`의 `id`는 기존 id의 최댓값 + 1이고, `last_month`는 마지막으로 지출을 만든 달이다. 그달에 없는 날(31일 등)은 말일로 만든다.
- 지출 한 건에 붙는 필드 중 기능 4 담당은 `weights`(없으면 `None`, 입력은 기능 1이 받음)와 `recurring_id`(없으면 `None`)다. 최상위 항목으로 옮기지 않는다.

### 18. duplicates · 같은 날·같은 사람·같은 금액 지출 찾기

```python
duplicates(store, date, payer, amount, exclude_id=None) -> list[int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/ledger.py` | 진영서 | 양정현(지출 추가·수정의 중복 의심 경고), 진영서(CSV 가져오기·합치기의 중복 행 감지) |

- **입력**
  - `date`: 날짜. `dates.fmt`로 `YYYY-MM-DD`로 바꿔 비교한다.
  - `payer`: 낸 사람 이름 `str`. 글자 그대로 비교한다.
  - `amount`: 금액. `money.to_won`으로 바꿔 비교한다(`"9,000"` → 9000).
  - `exclude_id`: 결과에서 뺄 지출 번호(양의 `int`) 또는 `None`. 수정할 때 자기 자신을 빼려고 쓴다.
  - **명부·회원 여부·잠금은 검사하지 않는다.** 찾기만 하는 함수다.
- **반환**: 조건이 맞고 삭제되지 않은 지출의 번호 목록, **번호 오름차순**. Store는 바꾸지 않는다. 경고 문구 출력은 부르는 쪽이 한다.
- **예시**
  ```python
  duplicates(S, "2026-11-17", "양정현", "9,000")                # → [1]
  duplicates(S, "2026-11-17", "양정현", 9000, exclude_id=1)     # → []
  duplicates(S, "2026-11-17", "신동훈", 9000)                   # → []   (낸 사람이 다름)
  duplicates(S, "2026-11-17", "양정현", 0)                      # → []   (0원 지출은 저장될 수 없으므로 맞는 것이 없음)
  # S의 e에 deleted=True를 넣으면
  duplicates(S, "2026-11-17", "양정현", 9000)                   # → []   (삭제된 지출 제외)
  ```
- **빈 자료**: 지출이 없거나 맞는 것이 없으면 `[]`. 명부에 없는 이름도 `[]`일 뿐 오류가 아니다.
- **오류**
  - 날짜: 없는 날짜, 형식이 틀린 날짜 → `dates.fmt`의 `ValueError` 그대로
  - 금액: 숫자로 읽을 수 없는 값, `bool`, `NaN`, 무한대 → `ValueError("금액 형식이 잘못되었습니다: …")`
  - `exclude_id`가 `None`도 양의 `int`도 아님(`bool` 포함) → `ValueError("제외 번호는 양의 정수여야 합니다")`
- **주의: validate와 오류 문구를 맞춘다**
  - 지출 추가는 duplicates를 insert(=validate)보다 **먼저** 부를 수 있다. 어느 쪽이 먼저 오류를 내도 사용자에게 같은 문구가 보이도록, 날짜는 `dates.fmt`의 오류를 그대로 쓰고 금액은 validate(01)처럼 `to_won` 호출을 `try/except (ValueError, ArithmeticError)`로 감싸 같은 문구로 바꾼다.
  - 0원 이하 금액은 **거부하지 않고 `[]`**를 돌려준다. "1원 이상" 검사는 validate 한 곳에서만 한다.

### 21. detect_encoding · 글자 인코딩 판별

```python
detect_encoding(path) -> str   # "utf-8-sig" 또는 "cp949"
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/csvio.py` | 진영서 | 진영서(CSV 가져오기), 김정빈(은행 거래내역 가져오기, 기본 CP949) |

- **입력**: 파일 경로(`str` 또는 `os.PathLike`)
- **동작**: 파일 전체를 바이트로 읽어 **UTF-8(BOM 허용)로 먼저** 엄격하게(`strict`) 풀어 보고, 실패하면 CP949로 풀어 본다.
- **반환**: `"utf-8-sig"` 또는 `"cp949"`. 영문·숫자만 있어 둘 다 되는 파일은 UTF-8이 먼저이므로 `"utf-8-sig"`. 파일은 바꾸지 않는다.
- **예시**
  ```python
  # u.csv 바이트: b"name,amount\nA,9000\n"
  detect_encoding("u.csv")   # → "utf-8-sig"
  # k.csv: "이름,금액\n"을 CP949로 저장 (b"\xc0\xcc\xb8\xa7,...")
  detect_encoding("k.csv")   # → "cp949"
  ```
- **빈 자료**: 0바이트 파일은 `"utf-8-sig"`
- **오류**
  - 두 인코딩 모두로 풀 수 없음 → `ValueError("UTF-8 또는 CP949로 읽을 수 없습니다: <경로>")`
  - 파일이 없음·권한 없음 → `FileNotFoundError` 등 `OSError` 그대로
- **주의**: 금액·날짜·열 이름이 맞는지는 이 함수가 보지 않는다.

### 22. read_csv_rows · CSV 읽기와 열 이름 연결

```python
read_csv_rows(path, mapping=None, encoding=None) -> tuple[str, list[tuple[int, dict]]]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/csvio.py` | 진영서 | 진영서(CSV 가져오기·미리 보기), 김정빈(은행 거래내역 가져오기) |

- **입력**
  - `mapping`: `{파일 열 이름: 필드 이름}` 또는 `None`
    - **파일에 없는 키는 무시한다.** 그래서 `{"날짜": "date", "거래일자": "date"}`처럼 한 필드에 열 이름 후보를 여러 개 둘 수 있다.
    - mapping에 없는 열은 파일의 열 이름 그대로 둔다.
  - `encoding`: `None`이면 `detect_encoding`으로 정한다. `"utf-8"`·`"utf-8-sig"`·`"cp949"`만 받는다.
- **반환**: `(쓴 인코딩, [(줄 번호, {필드: 값}), ...])`
  - 쓴 인코딩: UTF-8 계열은 **항상 `"utf-8-sig"`로 읽고 `"utf-8-sig"`를 돌려준다**(BOM이 있어도 첫 열 이름이 깨지지 않게).
  - 줄 번호: 그 행이 **시작하는 파일의 실제 줄 번호**. 머리글이 1번 줄이다. 빈 줄은 건너뛰지만 뒤 행의 번호는 실제 줄 번호를 지킨다. 따옴표 안에서 줄이 바뀌는 행은 시작한 줄 번호를 쓴다.
  - 값: 바꾸지 않은 문자열 그대로(공백 제거·숫자 변환 없음). 금액·날짜 변환은 부르는 쪽이 `money.to_won`·`dates.fmt`로 한다. 머리글 이름만 양끝 공백을 지운다.
  - 열 수가 맞지 않는 행도 돌려준다(`csv.DictReader` 방식). 모자란 열의 값은 `None`, 남는 값은 키 `None`에 `list[str]`로 담긴다. **부르는 쪽은 이런 행을 그 줄 번호의 오류로 보고한다.**
- **예시**
  ```python
  # b.csv (UTF-8):
  # 1 거래일자,금액
  # 2
  # 3 2026-11-17,"9,000"
  # 4 2026-11-18
  read_csv_rows("b.csv", {"날짜": "date", "거래일자": "date", "금액": "amount"})
  # → ("utf-8-sig", [(3, {"date": "2026-11-17", "amount": "9,000"}),
  #                  (4, {"date": "2026-11-18", "amount": None})])     # 4번 줄은 열이 모자람 → 부르는 쪽이 오류로 보고
  ```
- **빈 자료**: 빈 파일이나 머리글만 있는 파일은 `(쓴 인코딩, [])`
- **오류**
  - `ValueError`: 빈 머리글 이름, 머리글 이름 중복, mapping 결과 **실제 파일의 두 열이 같은 필드 이름**이 됨, 받지 않는 `encoding`, dict가 아닌 mapping, 두 인코딩 모두로 풀 수 없음
  - `OSError`: 파일이 없거나 읽을 수 없음
- **주의**: Store를 읽거나 바꾸지 않는다. 필수 열(예: date·amount)이 빠졌는지는 부르는 쪽이 검사한다.
- **먼저 필요한 것**: 21 detect_encoding

### A3. Store.record · 이력 남기기

```python
store.record(action, eid, before, after) -> None
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/store.py` | 양정현 | 02 insert, 지출을 바꾸는 모든 함수 |

- `store.data["history"]` 끝에 이력 하나를 붙인다. 메모리만 바꾸고 디스크에는 저장하지 않는다.
- **이력 한 건의 모양**
  ```python
  {"at": "2026-11-18T14:05:00",   # 기록한 시각
   "action": "edit",              # 아래 표의 값
   "id": 1,                       # 지출 번호
   "before": {...} or None,       # 바꾸기 전 지출 (깊은 복사)
   "after":  {...} or None}       # 바꾼 뒤 지출 (깊은 복사)
  ```
- **action 값**

  | action | 언제 | before | after | 담당 |
  | --- | --- | --- | --- | --- |
  | `INSERT_ACTIONS`의 값 | 새 지출 추가 | **`None`** | 새 지출 | insert |
  | `"edit"` | 지출 수정 | 수정 전 | 수정 후 | 양정현 |
  | `"delete"` | 삭제 표시 | 삭제 전 | `deleted=True`인 지출 | 양정현 |
  | `"restore"` | 되살리기 | 되살리기 전 | `deleted=False`인 지출 | 양정현 |
  | `"undo"` | 직전 수정 되돌리기 | 되돌리기 전 | 되돌린 후 | 양정현 |

  - 새 지출의 `before`는 `{}`가 아니라 **`None`**이다. `{}`는 "키가 하나도 없던 지출"과 헷갈리기 때문이다.
  - 삭제는 지우는 게 아니라 표시만 하므로 `after`도 지출 dict다.

### A1. money.check_weights · 비율 검사 (기준을 가진 한 곳)

```python
check_weights(members, weights) -> dict[str, int]
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/money.py` | 이은경 (weights 필드를 가진 기능 4) | 01 validate, 09 split |

- **왜 필요한가**: 비율 검사 기준이 validate와 split 두 곳에 따로 있으면, 한쪽만 바뀌었을 때 "validate는 통과했는데 split에서 오류"가 생긴다. **기준은 이 함수 한 곳만 가진다.** 기준을 바꿀 때도 이 함수만 고친다.
- **입력**: `members`: 참여자 목록, `weights`: `dict[str, int]` 또는 `None`
- **반환**: 참여자 순서의 `{이름: 비율}`. 빠진 이름은 `1`, `None`이나 `{}`는 모두 `1`이다.
- **예시**
  ```python
  check_weights(P, None)            # → {"양정현": 1, "신동훈": 1, "이은경": 1}
  check_weights(P, {"양정현": 2})   # → {"양정현": 2, "신동훈": 1, "이은경": 1}
  check_weights(P, {"김철수": 1})   # → ValueError (참여자가 아닌 이름)
  ```
- **오류**: dict가 아님, 참여자가 아닌 key, 0·음수·`bool`·정수가 아닌 비율
- **주의**: 팀이 더한 함수라 채점 때 바뀌지 않는다.

### A4. Store.save · 안전 저장 (내용 바꾸기)

```python
store.save() -> None
```

| 파일 | 담당 | 쓰는 사람 |
| --- | --- | --- |
| `moim/common/store.py` | 이은경 (자료 파일 손상 대응) | 김정빈(통합 실행이 명령 뒤에 호출) |

- 이름과 인자는 그대로 두고 내용만 바꾼다.
- **동작 순서**
  1. 주 자료 파일이 있으면 `backup_dir`에 `<자료파일명>.<YYYYMMDD_HHMMSS_ffffff>.<8자리 16진수>.bak`로 복사한다.
  2. 같은 폴더의 임시 파일에 JSON을 쓰고, 닫은 뒤 `os.replace`로 주 파일과 바꾼다. 저장 도중 멈춰도 주 파일이 깨지지 않는다.
  3. 백업이 `keep`(기본 10)개를 넘으면 가장 오래된 것부터 지운다.
- **반환**: `None`. 실패하면 예외를 그대로 올린다.
- **주의**: 저장할 때 `history`, `locks`, `transfers`, `recurring`, `payments`와 모르는 키를 모두 그대로 둔다.
