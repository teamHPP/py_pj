# 공통 모듈 함수 규격

> 작성일: 2026-11-18 · 상태: **내용을 모두 채운 팀 검토용 완성안**. 실제 팀 승인이나 코드 구현 완료를 뜻하지 않는다.
> 함수 이름·인자·기존 주석·기본 테스트·규약의 계약은 유지한다. 소스에 없던 세부 동작은 아래와 같이 일관되게 선택한 **추가 합의안**이다. 별도 MD 파일명·양식은 과제 지정 사항이 아니다.

## 공통 기준과 예시 자료

- 대상은 미구현 부분이 남은 공통 함수·메서드 22개이다. `money.split`은 기존 균등 분배를 유지하고 비율 분기만 추가한다. `self`는 Store 메서드의 객체 인자로, `store.backups()`처럼 호출할 때 따로 적지 않는다.
- 각 절은 ①소스의 함수 이름·인자와 담당 ②입력 자료형·의미 ③반환 구조 ④입력·결과 예 ⑤자료 없음 ⑥잘못된 입력 ⑦사용 담당 순서이다. 예시는 구현 코드가 아니라 앞으로 만족시킬 동작이다.
- 금액 저장은 bool을 제외한 원 단위 정수, 지출 금액은 양수다. 입력 소수는 기존 `money.to_won`의 사사오입을 사용한다. `split`의 계산용 금액 0 허용과 지출 등록의 0원 거부를 구분한다.
- 날짜 입력 `str/date/datetime`은 기존 `dates.parse`와 같이 해석한다. 저장 날짜는 `YYYY-MM-DD`, 월 이름은 `YYYY-MM`이다. 시간대 변환 없이 datetime의 날짜 부분을 사용한다.
- 기간 양끝 포함·삭제 지출 기본 제외·회원 가입일/탈퇴일 당일 포함·규약의 나머지 순서는 변경하지 않는다. 집계는 현재 탈퇴 여부로 과거 지출을 지우지 않는다.
- 추가 합의안: 기간 조회·집계의 start/end=None 경계는 제한 없음, 지출 조회는 `(date,id)`순 깊은 복사, 0건 집계는 빈 사전/목록 또는 0, 부분 비율의 누락 이름은 1이다. 날짜 하나를 받는 on/value=None 허용을 뜻하지 않으며 기존 코드의 지원 완료 주장도 아니다.
- 아래 S는 정상 Store 객체이며, 각 예시는 **아래 초기 상태의 독립 복사본**에서 시작한다. 명부 이름은 표시된 문자열과 정확히 같고, 기존 지출의 추가 필드 누락은 deleted=False·weights=None·category_fixed=False로 읽는다. 알 수 없는 추가 필드는 보존한다.

```python
P = ["양정현", "신동훈", "이은경"]
e = {
    "id": 1, "date": "2026-11-17", "payer": "양정현", "amount": 9000,
    "members": P, "category": "식비", "memo": "회의 후 저녁",
    "deleted": False, "weights": None, "category_fixed": False,
    "recurring_id": None,
}
S.data = {
    "members": [
        {"name": "양정현", "joined": "2026-09-01", "left": None},
        {"name": "신동훈", "joined": "2026-09-01", "left": "2026-11-30"},
        {"name": "이은경", "joined": "2026-09-01", "left": None},
    ],
    "expenses": [e], "next_id": 2, "locks": [], "history": [],
    "payments": [], "transfers": [], "recurring": [],
}
```

## 담당별 규격

## 양정현 담당

### 01. validate
1. 함수·위치·담당: `validate(store, date, payer, amount, members, weights=None)` / `moim/common/ledger.py:7` / 양정현.
2. 입력: Store, 날짜 문자열·date·datetime, 낸 사람 str, 유한한 str·int·float·Decimal 금액, 중복 없는 비어 있지 않은 참여자 list[str], 비율 dict[str,int] 또는 None. 낸 사람·참여자 모두 명부와 당일 재적을 검사하고 잠금일은 거부한다. 부분 비율의 누락자는 1로 센다.
3. 반환: `(정규화한 YYYY-MM-DD 문자열, 사사오입한 int 원)` 튜플. 날짜는 `dates.fmt`, 금액은 `money.to_won` 규약을 따르며 Store·입력 목록·비율을 변경하거나 저장하지 않는다.
4. 정확한 예: `validate(S, "2026-11-17", "양정현", "9,000", P)` → `("2026-11-17", 9000)`; 금액 `"2.5"`이면 같은 날짜와 `3`을 반환한다.
5. 자료 없음: 빈 명부에서 호출하면 등록되지 않은 사람이라는 ValueError. 빈 참여자는 ValueError이며, 지출이 아직 없는 것 자체는 오류가 아니다.
6. 잘못된 입력: 0 이하로 정규화되는 금액·bool·NaN·무한대·없는 날짜·재적 밖 사람·잠금일·중복 참여자·참여자 밖 비율 키·0/음수/bool/비정수 비율은 이유를 담은 ValueError. 예: `members=[]` → `ValueError("참여자가 비어 있습니다")`.
7. 사용 담당: 양정현의 추가·수정, 진영서의 가져오기 검사·미리보기. 이은경·김정빈·진영서는 지출 삽입 시 `insert`를 통해 이 검사를 공유한다.

### 02. insert
1. 함수·위치·담당: `insert(store, date, payer, amount, members, memo="", weights=None, category=None, recurring_id=None, action="add")` / `moim/common/ledger.py:18` / 양정현.
2. 입력: store/date/payer/amount/members/weights의 검사는 `validate`와 같고, memo는 str, category는 str 또는 None, recurring_id는 양의 int 또는 None, action은 비어 있지 않은 str. 목록·비율은 독립 복사하고 누락 비율은 1로 해석한다.
3. 반환: 저장한 새 지출 dict의 독립 복사본. 검사 성공 뒤 메모리에 지출·다음 번호·추가 이력 1건만 함께 반영한다. 디스크 저장은 하지 않으며 CLI가 `Store.save()`를 호출한다. 중복 의심 자체는 삽입 거부 사유가 아니다.
4. 정확한 예: 초기 S에서 `insert(S,"2026-11-18","양정현",9000,P,category="식비")` → `{"id":2,"date":"2026-11-18","payer":"양정현","amount":9000,"members":P,"memo":"","weights":None,"category":"식비","deleted":False,"category_fixed":False,"recurring_id":None}`; S의 next_id는 3. 이 예시는 나열한 기본 필드를 갖춘 초기 자료를 전제로 하며 추가 필드의 존재를 금지하지 않는다.
5. 자료 없음: 지출 목록이 비어 있고 유효한 명부와 next_id=1이 있으면 1번부터 추가한다. 명부·참여자·필수 자료 형식이 없으면 ValueError이며 빈 지출을 만들지 않는다.
6. 잘못된 입력: `validate`의 오류, 잘못된 memo/category/recurring_id/action·next_id는 이유를 담은 ValueError. 실패하면 expenses·next_id·history를 포함한 Store 전체가 호출 전과 같아야 한다.
7. 사용 담당: 양정현의 지출 추가·파일 입력, 이은경의 반복 지출, 김정빈의 은행 출금 가져오기, 진영서의 CSV 가져오기·모임 자료 병합.

## 신동훈 담당

### 03. category_of

1. 함수·담당: `category_of(e)` / `moim/common/queries.py:17` / 신동훈.
2. 입력: `e: dict`; `category`는 분류 이름 `str` 또는 `None`이며 필드 누락도 허용한다.
3. 반환: 분류 이름 `str`; 앞뒤 공백을 제거하고, 누락·`None`·공백뿐인 문자열이면 규약의 `"미분류"`를 반환한다. 입력 dict는 변경하지 않는다.
4. 예시: `category_of(e)` → `"식비"`; `category_of({"category": None})` → `"미분류"`.
5. 자료 없음: `category_of({})` → `"미분류"`; 정상적인 미분류는 오류가 아니다.
6. 잘못된 입력: dict가 아닌 e, 문자열/None이 아닌 category 값은 `ValueError`.
7. 사용 담당: 성수빈(보고서), 김정빈(분류별 예산), 진영서(분류 선택 내보내기).

### 04. category_totals

1. 함수·담당: `category_totals(store, start, end)` / `moim/common/queries.py:22` / 신동훈.
2. 입력: `store: Store`; start/end는 날짜 `str | datetime.date | datetime.datetime | None`. None인 쪽은 기간 제한이 없고, 두 날짜가 있으면 시작≤끝이며 양끝을 포함한다.
3. 반환: `dict[str, dict[str, int]]`, 정확히 `{분류: {"count": 건수, "amount": 원정수}}`; 삭제 제외, 미분류는 category_of 기준, 실제 지출이 있는 분류만 포함한다. 원본 변경 없음.
4. 예시: `category_totals(S, "2026-11-01", "2026-11-30")` → `{"식비": {"count": 1, "amount": 9000}}`.
5. 자료 없음: 해당 지출이 없으면 `{}`; 미사용 분류를 0건으로 추가하지 않는다.
6. 잘못된 입력: 잘못된 날짜·역순 기간·잘못된 지출 금액/분류/삭제 표시 또는 자료 구조는 `ValueError`.
7. 사용 담당: 성수빈, 김정빈. 성수빈은 보고서 by_category에 필요한 경우 amount만 추출하며 공통 반환형은 바꾸지 않는다.

## 성수빈 담당

### 05. expenses_in

1. 함수·담당: `expenses_in(store, start, end, include_deleted=False)` / `moim/common/queries.py:7` / 성수빈.
2. 입력: `store: Store`; start/end는 날짜 `str | datetime.date | datetime.datetime | None`; include_deleted는 bool. None 경계는 열린 구간, 두 경계가 있으면 시작≤끝, 양끝 포함.
3. 반환: `list[dict]`; deleted 누락은 False로 보고 기본은 deleted=True 제외, include_deleted=True면 포함한다. `(date, id)` 오름차순의 독립적인 깊은 복사이므로 결과 수정이 원본에 영향을 주지 않는다.
4. 예시: `expenses_in(S, "2026-11-17", "2026-11-17")` → `[e와 내용이 같은 독립 dict]`; `expenses_in(S, None, None)`도 이 예제에서는 같은 내용이다.
5. 자료 없음: 빈 저장소·일치 지출 없음은 `[]`; 삭제 지출만 있고 기본 옵션인 경우도 `[]`.
6. 잘못된 입력: 날짜 오류·역순 기간·bool이 아닌 include_deleted·지출 목록/id/date/deleted의 잘못된 자료형은 `ValueError`.
7. 사용 담당: 전원. 이은경의 기간 정산·부담액, 진영서의 내보내기, 김정빈의 예산 등에서 공통으로 사용한다.

### 06. person_paid

1. 함수·담당: `person_paid(store, start, end)` / `moim/common/queries.py:27` / 성수빈.
2. 입력: `store: Store`; start/end는 날짜 `str | datetime.date | datetime.datetime | None`. None 경계는 제한 없음, 두 날짜는 시작≤끝, 양끝 포함.
3. 반환: `dict[str, int]`, `{낸사람: 해당기간 실제 지출액 합계}`. 삭제 제외, 실제 낸 사람만 key로 포함하며 합산 중 현재 탈퇴자를 제거하지 않는다. 원본 변경 없음.
4. 예시: `person_paid(S, "2026-11-01", "2026-11-30")` → `{"양정현": 9000}`; 0원 key가 필요한 호출자는 `.get(이름, 0)`을 사용한다.
5. 자료 없음: 일치 지출이 없으면 `{}`; 안 낸 회원 전체를 자동 추가하지 않는다.
6. 잘못된 입력: 날짜 오류·역순 기간·낸 사람/금액/삭제 표시 등 집계에 필요한 지출 자료 오류는 `ValueError`.
7. 사용 담당: 이은경(정산의 paid), 성수빈(사람별 보고서). 부담할 돈 owed와 구분한다.

### 07. table
1. 함수·위치·담당: `table(headers, rows, total=None, numeric=None)` / `moim/common/textfmt.py:18` / 성수빈.
2. 입력: 비어 있지 않은 headers list[str], 같은 열 수의 rows list[list[str|int]], 같은 열 수의 합계 행 total 또는 None, 0부터 세는 오른쪽 정렬 열 번호 집합 numeric 또는 None. bool은 숫자 셀로 받지 않는다.
3. 반환: str 한 개. 정수는 천 단위 쉼표, numeric 열의 자료는 오른쪽 정렬, 나머지는 왼쪽 정렬한다. 제목은 왼쪽 정렬, 셀 사이 두 칸, 행 사이 `\n`, 각 행 끝 공백·최종 개행은 없다. `width`로 구한 열 폭만큼 `-`를 넣은 구분선을 첫 자료 행 앞과 total 앞에 각각 두며, rows가 없으면 자료 행 앞 선도 없다. 출력·저장은 하지 않는다.
4. 정확한 예: `table(["A"],[["B"]])` → `"A\n-\nB"`; `table(["금액"],[[9000]],total=[9000],numeric={0})` → `"금액\n-----\n9,000\n-----\n9,000"`.
5. 자료 없음: `table(["금액"], [], numeric={0})` → `"금액"`; `table(["A"], [], total=["T"])` → `"A\n-\nT"`.
6. 잘못된 입력: 빈 제목·열 수 불일치·범위 밖/비정수/bool 열 번호·지원하지 않는 셀 타입은 ValueError. 예: `table(["금액"],[[9000,1]])` → `ValueError("행의 열 수가 제목과 다릅니다")`.
7. 사용 담당: 성수빈의 보고서, 양정현의 목록, 이은경의 정산, 김정빈의 예산 명령. 명령 담당이 반환 문자열을 출력한다.

### 08. bar_chart
1. 함수·위치·담당: `bar_chart(data, bar_width=30, char="#")` / `moim/common/textfmt.py:23` / 성수빈.
2. 입력: 입력 순서를 유지할 dict[str,int]의 비음수 원 금액, 양의 int bar_width, 화면 폭이 1칸인 한 문자 str char. bool 금액·폭, 줄바꿈·제어문자 char는 허용하지 않는다.
3. 반환: str 한 개. 막대 길이는 `값 × bar_width // 최댓값`, 모두 0이면 0칸이다. 이름은 `width` 기준 최대 이름 폭에 왼쪽 정렬하며 한 줄은 `정렬한 이름 + " | " + 막대 + " " + 천 단위 금액`이다. dict 삽입 순서대로 `\n`으로 잇고 최종 개행은 없다. 출력·저장은 하지 않는다.
4. 정확한 예: `bar_chart({"식비":2,"교통":1},bar_width=4)` → `"식비 | #### 2\n교통 | ## 1"`.
5. 자료 없음: `{}` → `""`; `{"식비":0}` → `"식비 |  0"`이며 구분자 뒤 두 공백 사이는 길이 0인 막대다.
6. 잘못된 입력: 음수·비정수·bool 금액, 0 이하/비정수/bool 폭, 두 글자·빈 문자열·두 칸 폭 char는 ValueError. 예: `bar_chart({"식비":-1})` → `ValueError("막대 값은 0 이상의 정수여야 합니다")`.
7. 사용 담당: 성수빈의 분류별·월별 보고서, 표·그래프가 필요한 명령 담당. 이은경·양정현·김정빈이 사용해도 같은 문자열 계약을 따른다.

## 이은경 담당

### 09. split

1. 함수·담당: `split(amount, members, payer=None, weights=None)` / `moim/common/money.py:30` / 이은경. 기존 균등 분배를 보존하고 비율 분배를 추가한다.
2. 입력: amount는 bool을 제외한 0 이상 int, members는 중복 없는 비어 있지 않은 list[str], payer는 이름 str/None. weights는 dict[str, 양의 int]/None이며 bool 값·참여자 외 key는 금지, 누락 key는 1, None/{}는 전원 1이다.
3. 반환: 참여자 순서의 `{이름: int부담액}`; 비율대로 원 미만을 버리고 남는 원은 payer가 참여자이면 먼저, 이후 참여자 목록 순서로 배분한다. 합계는 amount이며 입력 변경 없음; payer가 참여자가 아니어도 허용한다.

### 20. month_key

2. 입력: value는 날짜 str/date/datetime이며 dates.parse와 같은 날짜 해석을 따른다. datetime은 주어진 객체의 date 부분을 쓰며 별도 시간대 변환은 하지 않는다.
3. 반환: 0을 채운 연월 `str`, 형식 `"YYYY-MM"`; 원본 변경·저장 없음.
4. 예시: `month_key("2026-11-17")` → `"2026-11"`; `month_key(datetime.date(2026,1,2))` → `"2026-01"`.
5. 자료 없음: None/빈 문자열은 유효한 날짜가 아니므로 반환 기본값을 만들지 않는다.
6. 잘못된 입력: None·지원하지 않는 자료형·실제 없는 날짜·잘못된 날짜 문자열은 `ValueError`.
7. 사용 담당: 성수빈(월별 보고서), 진영서(월별 입출력 자료 구분).

### 21. detect_encoding
1. 함수·위치·담당: `detect_encoding(path)` / `moim/common/csvio.py:6` / 진영서.
2. 입력: 읽을 파일의 비어 있지 않은 str 또는 PathLike 경로. 파일 전체를 UTF-8(BOM 허용) strict로 먼저 판독하고 실패하면 CP949 strict로 판독한다.
3. 반환: `"utf-8-sig"` 또는 `"cp949"` str. 둘 다 가능한 ASCII 파일은 UTF-8 우선 정책에 따라 `"utf-8-sig"`. 파일 내용·Store·설정은 변경하지 않는다.
4. 정확한 예: 파일 `u.csv`의 바이트가 `b"name,amount\nA,9000\n"`이면 `detect_encoding("u.csv")` → `"utf-8-sig"`; CP949로만 읽히는 한글 파일이면 `"cp949"`.
5. 자료 없음: 0바이트 파일은 `"utf-8-sig"`. 파일 부재는 빈 자료가 아니며 FileNotFoundError를 전달한다.
6. 잘못된 입력: 두 인코딩 모두 판독 불가면 `ValueError("UTF-8 또는 CP949로 읽을 수 없습니다")`; 빈 경로·잘못된 경로 타입은 ValueError, 파일 부재·권한 등은 OSError 계열.
7. 사용 담당: 진영서의 CSV 가져오기·공통 CSV 읽기, 김정빈의 은행 거래내역 가져오기. 금액·날짜·열 이름의 의미 검사는 이 함수에서 하지 않는다.

### 22. read_csv_rows
1. 함수·위치·담당: `read_csv_rows(path, mapping=None, encoding=None)` / `moim/common/csvio.py:11` / 진영서.
2. 입력: 파일 경로, `{외부 열 이름: 내부 필드 이름}` mapping 또는 None, `"utf-8"`·`"utf-8-sig"`·`"cp949"` encoding 또는 None. None이면 detect_encoding을 사용하고 UTF-8 계열은 `"utf-8-sig"`로 읽고 반환한다. 헤더 양끝 공백만 제거하고 값 문자열은 변환·공백 제거하지 않는다.
3. 반환: `(encoding, [(레코드 시작 물리 줄 번호:int, 행 dict)])`. 정상 행은 dict[str,str]; 열 수 오류 행까지 포함한 전체 타입은 dict[str|None,str|None|list[str]]이다. 미지정 열 이름은 유지하며 짧은 행의 누락 값은 None, 긴 행의 초과 값은 `None` 키의 list[str]로 보존하는 csv.DictReader 관례를 따른다. 호출자가 그 줄만 오류로 보고할 수 있게 반환한다.
4. 정확한 예: UTF-8로 저장한 파일 내용이 `거래일자,금액\n2026-11-17,"9,000"\n`이고 mapping=`{"거래일자":"date","금액":"amount"}`이면 `("utf-8-sig",[(2,{"date":"2026-11-17","amount":"9,000"})])`. 인용 필드가 여러 물리 줄이어도 번호는 그 레코드가 시작된 줄이다.
5. 자료 없음: 빈 파일·헤더만 있는 파일은 `(선택한 encoding, [])`. 빈 물리 줄은 건너뛰되 뒤 레코드의 실제 줄 번호는 유지한다.
6. 잘못된 입력: 빈/중복 헤더, 헤더가 있는 파일에서 존재하지 않는 mapping 키, 변환 후 필드 이름 중복, 잘못된 mapping/encoding, 판독 불가·행 경계를 복구할 수 없는 CSV 문법은 ValueError; 파일 접근은 OSError 계열. 열 수 불일치·숫자/날짜 값 오류는 호출자가 해당 줄만 errors에 모아 건너뛴다.
7. 사용 담당: 진영서의 지출 CSV 가져오기·미리보기, 김정빈의 은행 가져오기. 두 호출자는 `None` 키/값을 열 수 오류로 판정하고 정상 행만 도메인 검사하며, 가져온 금액·날짜를 각 공통 함수로 변환한다. 이 읽기 함수는 Store를 수정·저장하지 않는다.

## 공동 업무와 연결할 때 유지할 사항

- `Store.load()`는 기존대로 self, `Store.save()`는 정상 완료 시 None을 반환한다. 저장 실패는 예외로 전달하고 주 자료 저장은 통합 실행에서 처리한다. 자동 저장은 직전 정상본 백업과 안전한 교체를 거치며 최근 10개를 유지한다. 자동 백업 이름은 `<자료파일명>.<YYYYMMDD_HHMMSS_ffffff>.<고유값>.bak`으로 충돌을 피한다.
- 진영서가 설정의 자료·백업·로그 경로를 준비하고 김정빈이 Store·로거에 전달한다. `config.load()`는 설정 dict, `config.save_default()`는 정상 완료 시 None, `get_logger()`는 logging.Logger라는 기존 반환 계약을 유지한다.
- 개인 명령의 `run()`은 자료 변경 시 True, 조회·미리보기는 False를 반환한다. 이는 기능 함수의 계산 결과나 Store.save의 반환과 다른 계약이다. 출력은 명령 계층에서 한다.
- `Store.record`는 양정현이 추가할 함수이므로 현재 22개와 분리한다. 공유 자료의 history·locks·payments·transfers·recurring과 추가 필드는 저장·백업·복구 과정에서 보존한다. 지출별 weights·deleted·category_fixed를 최상위 항목으로 옮기지 않는다.
- 진영서의 지출 내보내기는 전체 Store 백업과 구분한다. 전체 복원을 선택 구현할 때에는 회원·입금·이력·잠금까지 포함할지 별도 범위를 명시한다.
- 본문은 제안 정책을 모두 정한 완성안이다. 실제 팀 검토 후 바뀐 규격은 함수 담당자와 사용자에게 함께 알리고, 최종 합의 날짜와 문서 버전을 기록한다.
