# 팀원별 구현 가이드 (3팀)

> **아직 저장소에 올리지 않은 초안입니다.** 양정현 검토·승인 후에 PR로 올립니다.
> 공고문·스켈레톤 구조 문서·`docs/공통모듈_함수규격.md`·`docs/협업규칙합의문.md`를 바탕으로,

## 전체 흐름 (공통, 먼저 읽기)

작업은 4단계다. 순서를 틀리면 테스트가 계속 "건너뜀"으로만 나온다.

| 단계 | 내용 | 목표일 |
| --- | --- | --- |
| 1단계 | 바닥 공통 함수 5개 (기능 1·3·4·5·6) | 11/21(토) 12:00 |
| 2단계 | 각자의 공통 함수 (기능 2~6 나머지) | 11/22(일) |
| 3단계 | 기본 필수 4개 + 명령 + 테스트 | 11/24(화) 12:00 (마감 23:59지만 정오를 1차 목표로) |
| 4단계 | 확장 필수 4개 + 선택 2개 이상 + 팀 공동 작업 | 12/1(화) |

- **1단계 병합 순서**: 양정현 → 이은경 → 김정빈 → 진영서 → 성수빈. 한 명씩 병합하고 바로 팀 채팅에 공지 — 다음 사람이 바로 `main`을 받아가게.
- **다른 사람을 기다리지 않는 법**: 내 테스트에서는 `add_expense` 대신 `store.data["expenses"]`에 지출 dict를 직접 넣어서 먼저 시험할 수 있다. 남이 채울 공통 함수는 이름·인자가 이미 정해져 있으니, 그 함수를 부르는 내 코드는 먼저 써 둬도 된다.
- **충돌 잦은 파일 — 조심할 것**: `moim/common/store.py`의 `EMPTY`(기능 1·4·5가 항목 추가, 한 PR에 한 항목만), `moim/common/queries.py`(6명이 각자 함수만 채움). 올리기 전 항상 `git pull origin main`.
- **PR 규칙**: 한 PR = 변경 1건, 300줄 이하, 테스트 동봉. PR 설명에 변경 내용/이유/확인 방법(자동 검사 3종 결과) 적기.

## 양정현 · 기능 1 지출 입력·관리 (+ 팀 공동 작업: 통합 시나리오 테스트)

**1단계 바닥 함수** — 가장 먼저, 기능 2~6 전부가 기다림
- `ledger.validate(store, date, payer, amount, members, weights=None) -> tuple[str, int]`
- `ledger.insert(store, date, payer, amount, members, memo="", weights=None, category=None, recurring_id=None, action="add") -> dict`
- `store.py`의 `EMPTY`에 `history: []`, 지출 항목에 `deleted` 추가

**2단계**: 없음 — 1단계에서 이미 다 채워서 바로 3단계로 넘어감

**3단계 기본 필수 4개 (11/24까지)**
- [ ] 지출 추가(날짜, 낸 사람, 금액, 참여자, 메모, 사람별 비율)
- [ ] 지출 목록 보기(번호순, 날짜순)
- [ ] 지출 수정과 삭제(번호로 지정, 삭제는 삭제 표시만)
- [ ] 입력 검증(음수·0원 금액, 없는 날짜, 빈 참여자, 명부에 없는 사람(낸 사람 포함) 거부+이유 안내)
- 파일: `moim/features/expenses.py`, `moim/commands/expenses.py`

**4단계 확장 필수 (12/1까지)**
- [ ] 참여자 명부 관리(가입일·탈퇴일 기록, 회원 기간 밖 날짜는 참여자 불가)
- [ ] 수정·삭제 이력 기록·조회
- [ ] 여러 줄 한꺼번에 입력(파일에서 읽기), 잘못된 줄은 줄 번호+이유 보고
- [ ] 같은 날·금액·사람 중복 의심 경고 (`ledger.duplicates` 활용, 진영서 담당)

**선택 (2개 이상)**: 삭제한 지출 되살리기 / 직전 수정 되돌리기 / 삭제된 지출까지 보이는 목록

**팀 공동 작업 — 통합 시나리오 테스트**: 한 달치 자료로 입력→분류→보고서→정산→내보내기를 이어서 실행해 합계가 모두 같은지 확인 (기능 6개가 어느 정도 갖춰져야 함, 4단계 작업)

- `queries.category_totals(store, start, end) -> dict` (성수빈의 `expenses_in` 필요)

**3단계 기본 필수 4개 (11/24까지)**
- [ ] 메모의 키워드로 지출을 분류(식비, 교통, 장소 대여, 물품 등)
- [ ] 분류 규칙을 JSON 파일로 저장하고 읽기
- [ ] 규칙 추가·삭제·목록 명령
- [ ] 분류되지 않은 지출 목록

**4단계 확장 필수 (12/1까지)**

**선택**: 낸 사람·금액 범위로 분류하는 규칙 / 규칙 겹침 검사 / 분류 결과 미리 보기

**팀 공동 작업 — 로그**: 실행한 명령과 오류를 날짜별 로그 파일에 기록

## 성수빈 · 기능 3 월별·기간 보고서 (+ 팀 공동 작업: 사용 설명서)

**3단계 기본 필수 4개 (11/24까지)**

- [ ] 기간을 지정한 합계
- [ ] 분류별 합계

- [ ] 지출 검색(기간, 사람, 금액 범위, 메모 낱말)

**선택**: 요일별·주별 지출 / 가장 많이 쓴 날·가장 큰 지출 상위 N개 / 여러 달 추이 표 / 보고서를 텍스트 파일로 저장

## 이은경 · 기능 4 정산 (+ 팀 공동 작업: 자료 파일 손상 대응)

**1단계 바닥 함수** — 기능 1·5와 한 묶음, insert()가 내부에서 호출
- `queries.is_locked(store, on) -> bool`
- `store.py`의 `EMPTY`에 `locks: []` 추가
- 목표: 11/21(토) 12:00, 양정현 다음 순서로 병합

**2단계**
- `money.split`의 비율 분배부 (`A1 check_weights` 필요, 이은경이 먼저 만든 함수)
- `queries.expense_shares(e) -> dict` (`split` 필요)
- `queries.member_shares(store, start, end) -> dict` (`expenses_in`+`expense_shares` 필요 — 성수빈 바닥함수 기다림)
- 자료 항목 `weights` · `transfers` · `recurring` 추가

**3단계 기본 필수 4개 (11/24까지)**
- [ ] 사람마다 낸 돈, 부담할 돈, 잔액(받을 돈 또는 보낼 돈)
- [ ] 나머지 1원 배분은 규약 문서의 방법을 따름
- [ ] 정산 기간 지정
- [ ] 모든 사람의 잔액 합이 0인지 검사
- 파일: `moim/features/settle.py`, `moim/commands/settle.py`

**4단계 확장 필수 (12/1까지)**
- [ ] 송금 횟수를 줄인 "누가 누구에게 얼마" 목록
- [ ] 가중치 분담(지출에 적힌 사람별 비율대로 부담 계산)
- [ ] 반복 지출(매월 같은 날 자동 생성, 그달에 없는 날은 말일로)
- [ ] 정산 확정(규약 문서의 규칙대로 잠금, 잔액 합이 0이 아니면 확정하지 않음)

**선택**: 이미 보낸 송금 기록 반영(부분 정산) / 정산 내역서 출력 / 특정 지출에서 특정 사람 빼기 / 정산 결과를 이전 정산과 비교

**팀 공동 작업 — 자료 파일 손상 대응**: `store.backups()`·`store.recover()`·`store.save()`(A4) — 저장할 때마다 백업 남기고, 저장 파일이 깨졌을 때 마지막 정상 백업으로 복구. 저장 도중 멈춰도 파일이 깨지지 않게 저장

## 김정빈 · 기능 5 예산·회비 (+ 팀 공동 작업: 통합 실행)

**1단계 바닥 함수** — 기능 1·4와 한 묶음, insert()가 내부에서 호출
- `queries.is_member_active(store, name, on) -> bool`
- 목표: 11/21(토) 12:00, 이은경 다음 순서로 병합

**2단계**
- `queries.active_members(store, on) -> list[str]` (`is_member_active` 필요, 자기 자신의 1단계 함수)
- `dates.months_between(start_ym, end_ym) -> list[tuple]` (선행 함수 없음)
- 자료 항목 `payments` 추가

**3단계 기본 필수 4개 (11/24까지)**
- [ ] 월 예산 설정(설정 파일)
- [ ] 이번 달 예산 초과 여부와 남은 금액
- [ ] 회비 입금 기록(누가 언제 얼마)
- [ ] 모임 통장 잔고(입금 합계 − 지출 합계)
- 파일: `moim/features/budget.py`, `moim/commands/budget.py`

**4단계 확장 필수 (12/1까지)**
- [ ] 분류별 예산과 분류별 초과 경보
- [ ] 예산의 80%를 넘으면 미리 경보
- [ ] 회비 미납자 목록(월별, 그달 1일이나 말일에 회원인 사람이 대상)

**선택**: 월말 예측(오늘까지 지출 ÷ 지난 일수 × 그달 일수) / 예산 대비 실제 지출 표 / 회비 덜 낸 사람 정산에서 차감 / 다음 달 예산 제안(최근 3개월 평균)

**팀 공동 작업 — 통합 실행**: `moim/cli.py` — `python -m moim` 하위명령 틀 완성, 오류 안내·로그·init 추가, 각 기능 하위 명령을 이 틀에 붙임

## 진영서 · 기능 6 가져오기·내보내기 (+ 팀 공동 작업: 설정 파일)

**1단계 바닥 함수** — `insert()` 부르기 "직전" 단계(`add_expense`)에서 먼저 실행되는 중복 체크
- `ledger.duplicates(store, date, payer, amount, exclude_id=None) -> list[int]`
- 목표: 11/21(토) 12:00, 김정빈 다음 순서로 병합

**2단계**
- `dates.month_key(value) -> str` (선행 함수 없음)
- `queries.period_total(store, start, end) -> int` (`expenses_in` 필요 — 성수빈 바닥함수 기다림)
- `csvio.detect_encoding(path) -> str` (선행 함수 없음)
- `csvio.read_csv_rows(path, mapping=None, encoding=None) -> tuple` (`detect_encoding` 필요, 자기 자신의 함수)

**3단계 기본 필수 4개 (11/24까지)**
- [ ] 지출 기록을 CSV 파일로 내보내기(엑셀에서 한글이 깨지지 않게)
- [ ] 지출 기록을 JSON 파일로 내보내기
- [ ] 기간·분류를 골라서 내보내기
- [ ] 내보낸 파일의 합계가 원래 기록의 합계와 같은지 검사
- 파일: `moim/features/transfer_io.py`, `moim/commands/transfer_io.py`

**4단계 확장 필수 (12/1까지)**
- [ ] CSV 가져오기(열 이름이 달라도 연결해 주는 설정)
- [ ] 글자 인코딩 판별(UTF-8, CP949) — 공통 모듈 함수로 만들어 기능 5의 은행 거래내역 가져오기도 쓰게 함
- [ ] 중복 행 감지와 오류가 있는 행 번호 보고
- [ ] 다른 모임 자료와 합치기

**선택**: 전체 자료 백업과 복원 / 내보낸 파일을 다시 읽어 원래 기록과 대조 / 가져오기 미리 보기(실제로 넣기 전에 줄·중복·오류만 보여주기)

**팀 공동 작업 — 설정 파일**: `moim/common/config.py` — 모임 이름, 참여자 명부 파일 위치, 자료 파일 위치, 총무, 월 예산과 분류별 예산, 1인당 월 회비, 경보 비율 관리. 명부 파일을 읽어 명부에 반영하는 명령 포함
